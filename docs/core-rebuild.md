# النواة الرقمية: البنية والحالة (2026-11-10)

بطلب المالك حُذف النظام السابق وبدأ المشروع من جديد على المشروع نفسه (Supabase `labeedsch_PC` وGitHub Pages). حسابات `auth.users` بقيت.

## الهجرات (في سجل Supabase)
0007 إعادة تهيئة · 0008 الأساس (منسوبون، فرق، أدوار، أنظمة، تدقيق) · 0009 الملفات والبيانات الخاصة ومفاتيح الأنظمة · 0010 مرفقات الشواهد وقواعد الفرق.

## البيانات
- `staff_members` سجل عام مهني؛ `staff_private` (الرقم الوظيفي والبريد والجوال) للمالك والإدارة فقط.
- `staff_teaching` (المرحلة والمواد والصفوف) للهيئة التعليمية؛ التخصص اختياري لبقية الفئات.
- `staff_position_history` يُملأ تلقائياً عند تغيير الفئة أو المسمى.
- `teams` + `team_memberships`: قائد واحد ونائب واحد نشطان كحد أقصى، إنهاء العضوية يحفظ السجل.
- ثلاث طبقات للهوية: المسمى الوظيفي (`job_titles`) ثم الأدوار (`roles`/`staff_roles`) ثم الصلاحيات (`permissions`/`staff_permissions`) لكل نظام وفريق.
- `staff_profile_items` (تسعة أقسام) و`professional_records` (المجالات الأربعة؛ الممارسات التعليمية للتعليمية فقط).
- حماية الاعتماد: لا يعتمد المنسوب سجله بنفسه، وتعديل السجل المعتمد يعيده إلى «مقدَّم».
- `audit_logs` تُكتب بمشغّلات على المنسوبين والفرق والعضويات والأدوار والصلاحيات والسجلات المهنية.

## الواجهة (site/)
دخول، لوحة النواة، المنسوبون (إضافة وتعديل وحسابات)، استيراد Excel (معاينة وتكرار وتراجع)، الملف المهني، الفرق وصفحة الفريق، الصلاحيات، مركز الربط، سجل التدقيق.

## الاختبار
اختُبرت سياسات RLS والمشغّلات بسيناريو SQL داخل معاملة تُلغى (19 فحصاً ناجحاً). واجهات الصفحات فُحصت نحوياً فقط ولم تُشغَّل في متصفح، والدالة core-api لم تُستدعَ فعلياً بعد.
