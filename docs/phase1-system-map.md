# المرحلة الأولى: خريطة النظام الحالي (مجتمع المعلمين الذكي → النواة الرقمية)

تاريخ الفحص: 2026-11-10 · الفحص قراءة فقط، لم يُعدَّل أي شيء.

## 1. البنية الحالية

- **الواجهة:** موقع ثابت HTML/JS في `site/` (18 صفحة) يتصل بـ Supabase مباشرة عبر `app.js`، ويُنشر على GitHub Pages (`pages.yml`).
- **قاعدة البيانات:** مشروع Supabase `labeedsch_PC` (PostgreSQL 17، منطقة ap-southeast-1). 7 هجرات مطبّقة (0001–0006)، 128 سياسة RLS، 34 دالة، 54 مشغّلاً.
- **الهوية الحالية:** `auth.users` ← `public.users` (4 أدوار: system_admin, principal, coordinator, teacher) ← `public.teachers.user_id` (اختياري وفريد).
- **ملاحظة:** الهجرات 0001–0005 غير موجودة في المستودع (الموجود 0006 فقط). يجب استخراجها من قاعدة البيانات لتوثيق المصدر.

## 2. البيانات الحالية

| الجدول | الصفوف | ملاحظة |
|---|---|---|
| teachers | 10 | كلها `source_type = system` (بيانات تجريبية على الأرجح)، لا يوجد تكرار في الأسماء |
| teacher_private | 10 | سجل لكل معلم، بلا فجوات |
| users | 2 | لا يرتبط أي معلم بحساب حالياً (`user_id` فارغ في الـ 10) |
| teacher_skills / achievements / plc_members / program_registrations | 50 / 30 / 35 / 27 | مرتبطة بمعرفات المعلمين، يجب حفظها كما هي |

التخصص مخزّن كنص في `teachers.specialty` (لا يوجد جدول مواد أو صفوف). لا توجد حالياً أي فئة غير المعلمين.

## 3. اعتماديات `teachers.id` (يجب ألا يتغير)

33 مفتاحاً خارجياً تشير إلى `teachers.id`، منها: الملف المهني، المؤهلات، التراخيص، المهارات، الأهداف، البرامج، المنشورات، الممارسات، أعضاء مجتمعات التعلم، المبادرات، الإنجازات، الشواهد، التوصيات.
**القرار المقترح:** يبقى `teachers.id` هو المعرّف المركزي للمنسوب كما هو، ويُضاف جدول مركزي جديد بنفس المعرّفات بدل إعادة ترقيمها.

## 4. التصنيف المبدئي

**أساسي يجب الإبقاء عليه:** users، teachers، teacher_private، professional_profiles، teacher_qualifications، teacher_licenses، skills، teacher_skills، audit_logs، import_jobs، system_settings، academic_years، وكل جداول الأنظمة التشغيلية (plc_*، programs، posts، teaching_practices، achievements، initiatives، evidence_*).

**يحتاج تطويراً:**
- `users.role`: قيد CHECK بأربعة أدوار ثابتة، ويُستبدل بنموذج أدوار وصلاحيات قابل للتوسع (وظيفة / دور تنظيمي / صلاحية نظام).
- `teachers`: يتحول إلى امتداد تعليمي لجدول المنسوبين، مع جعل `specialty` اختيارياً لبقية الفئات.
- `plc_groups` + `plc_members`: العضوية فيها خاصة بمجتمعات التعلم فقط (`role` = leader/member، بلا تواريخ نهاية). تنتقل بيانات الفرق والعضويات إلى جدول فرق مركزي مع بقاء العمليات التشغيلية (اجتماعات، مهام، نقاشات، ملفات) في جداول `plc_*`.
- `initiative_members`، `teacher_private.job_status`: تتوحد مع العضويات والسجل الوظيفي.

**قابل للدمج:** `plc_members` و`initiative_members` مع جدول عضويات الفرق المركزي المقترح.

**قابل للتعطيل (لا حذف):** `competencies` (0 صف، غير مستخدمة في الواجهة)، `ai_recommendations` (0 صف)، `indicator_snapshots` (0 صف)، `notification_settings` و`notifications` (0 صف).

**مرشح للحذف بعد التحقق فقط (لا شيء يُحذف الآن):**
- جداول بلا أي استخدام في `site/`: `competencies`, `saved_posts`, `saved_practices`, `practice_applications`, `practice_evidence`, `resources`, `content_reports`, `program_evaluations`, `initiative_outputs`, `plc_outputs`, `plc_proposals`، وكلها فارغة. لكنها جزء من وثيقة المتطلبات الأصلية، فالتوصية أن تبقى مبدئياً.
- الصفحات: لا صفحات مكررة. `plc.html` و`plc-group.html` متكاملتان، و`compat.css` طبقة توافق تُراجع لاحقاً.

## 5. بيانات تجريبية

المعلمون العشرة، و6 برامج، و30 إنجازاً، و20 ممارسة، و5 مجتمعات، وبيانات مجتمعات التعلم، كلها تبدو بيانات عرض (مصدرها `system`). لا تُحذف قبل تأكيدكم.

## 6. ملاحظات أمنية من فاحص Supabase

1. دوال `public_*` الست قابلة للاستدعاء من `anon` (مقصود للموقع العام)، ويجب مراجعة ما تُرجعه فقط.
2. 20 دالة SECURITY DEFINER قابلة للاستدعاء من `authenticated`. بعضها مقصود (دوال الصلاحيات مثل `is_admin`)، ويجب فحص كل واحدة قبل ربط أنظمة أخرى.
3. حماية كلمات المرور المسرّبة معطّلة في Supabase Auth. يُنصح بتفعيلها.
4. المفتاح في `config.js` من نوع publishable، وهذا آمن بتصميمه.

## 8. خطة المرحلة الثانية (مقترحة، لم تُنفَّذ)

هجرات إضافية فقط وقابلة للتراجع، دون المساس بالجداول الحالية:
1. `staff_members`: جدول مركزي، معرّفه = `teachers.id` للمعلمين الحاليين، مع الفئة والمسمى والحالة وتاريخ الانضمام.
2. `staff_categories` و`job_titles` كجداول مرجعية.
3. `staff_position_history` للسجل التاريخي.
4. ربط `teachers.id` بـ `staff_members.id` بمفتاح خارجي، وجعل المعلم امتداداً تعليمياً.
5. ترحيل الـ 10 معلمين وفحص تطابق العدد والمعرفات قبل وبعد.
